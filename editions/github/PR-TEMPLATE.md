# PR-TEMPLATE.md — github 底座审查包

PR 描述是审查入口，不是完成宣言。五个小节都必须填写；不适用的写“无”，不要留空。

## 做了什么

- 用结果语言说明变更，而不是逐文件复述。
- 对应 Issue 的验收条目编号。
- 如有偏离原方案，说明原因。

## 怎么验证

- 逐条贴出**真实执行过的命令与输出**（含退出码）；CI 链接必须对应当前 head SHA。
- 说明哪些检查在本地跑过、哪些只由 CI 跑。
- 未执行的检查写“未验证”，不得写“应该通过”。

## 没做什么

- 明确列出本次未覆盖的行为、边界与后续任务。
- 已知限制与暂时绕过的地方。
- 若删除了断言、新增了跳过或放宽了检查，必须在此说明理由与批准记录。

## 风险

- 回归风险、数据迁移、权限 / 安全、依赖变化、公开行为变化。
- 回退方式。
- 需要项目所有者决定的事项（有则同时把 Issue 标为 `NEEDS_HUMAN_DECISION`）。

## 关联 Issue

- `Closes #<number>` 或 `Refs #<number>`。
- 依赖的 Issue 编号及当前状态。
- 相关设计文档或前置 PR。
