## 1. 现有身份路径：静态事实及边界

以下路径均相对仓库根。测试名为静态定位，不意味着为本文执行过或证明侧车安全。

| 路径 | 可定位事实 | 限制 |
|---|---|---|
| `tools/talkdnd/src/chargen.rs::slug`, `sheet_with`, `valid_id`；`lib.rs::chargen_cmd` | `sheet_with` 从名称生成 slug，写入 Markdown combat 块的 `id`；slug 去撇号、把其他分隔转连字符并小写，保留 Unicode 字母数字。`valid_id` 只接受首位小写 ASCII/数字、后续小写 ASCII/数字/连字符、最多 80 字节。建卡写 `Characters/<id>.md`，加 campaign party，再调用 `from_chargen`。 | slug 可碰撞；Unicode slug 可能未通过 ASCII 校验。格式合法不代表唯一、不可变、出处可信或人与角色身份相同；创建并非多文件事务。 |
| `check.rs::sheets`, `find` | 先 Characters 后 NPCs，每目录路径排序；无法读取目录、目录项、文件或解析 combat 块时跳过；缺失非字符串 id/name 变空串。`find` 对 ID **或**名称大小写不敏感的精确匹配使用第一个 `.find`；仅无精确匹配时才要求名称前缀唯一。 | 重复 ID、同名、一个 ID 等于另一名称时第一个精确项胜出；它不是唯一性检查。返回列表不保证枚举完整；不存在匹配不能证明不存在角色。大小写折叠与文件系统大小写规则不是同一东西。 |
| `charsheet.rs::path`, `load`, `parse_char_file`, `store`, `commit`, `markdown_path` | `load` 先发现/选择 Markdown，以其 ID 找 `sheets/<id>.yaml`；没有文件则从 Markdown `migrate` 到内存；有文件则解析，并在特定标记存在时吸收所选 Markdown 的 combat 块和尾部。`parse_char_file` 检查版本和 controller，所示路径未核对内部 ID 与发现 ID/路径一致；`store` 校验内部 ID 格式后按内部 ID 写。`commit` 依次存 YAML、party、按 `cf.file` 写 Markdown；`markdown_path` 检查相对路径组成。 | 一个合法 ID 可以指向另一个结构化文件，读入值和写出位置可能不同；`file` 路径合法不等于同一角色或 symlink 安全性已证明。写入次序非跨文件原子。不可据此声称任意真实存档有错绑。 |
| `charsheet.rs::migrate`, `migrate.rs::detect`, `migrate_sheets` | 旧 Markdown 的 combat ID/name、相对路径和主体进入结构化角色；无 meta 时 `detect` 根据 `check::sheets` 和相应 YAML 是否存在推断旧 schema。`migrate_sheets` 发现同 ID 的 YAML 就跳过。 | 枚举跳过的条目不会参与判断；同 ID 文件存在也不能证明对应角色。自动创建 sidecar 或把空历史当没有选择均不可推断。 |
| `lib.rs::add_to_party`, `start.rs::party_ids`, `combat-sim/src/party.rs::PartyState`, `progress.rs::recipients`, `xp_add`, `level_up`, `purse_key` | campaign party 是 ID 列表，建卡添加时按字符串精确去重；party state 的 `members` 按 creature ID 作键。进度、XP/钱袋用 ID；显式目标经 `find`，`all/party` 从 campaign 列表取 ID；`level_up` 经发现角色及其 ID 读进度并决定结构化/Markdown 写路径。`party_ids` 无法读取或找不到时返回空。 | 引用是可用键，不是持久人物身份；重复或改 ID 可能共用或悬空进度、party。不能根据单个匹配自动重绑或移动历史。 |
| `charsheet.rs::rerunning_chargen_sheet_keeps_play_data`, `commit_rejects_sheet_paths_outside_the_save`；`tests/spells.rs::migration_skips_dirty_sheets_in_both_shapes`, `migration_without_integrity_manifest_keeps_every_sheet_byte_identical` | 现有合成测试分别检查重建保留指定游玩字段、拒绝 `../` 路径，以及法术迁移 dirty sheet 保护。 | 这些测试不证明全目录唯一性、身份绑定、外部写者、克隆或 sidecar 恢复。当前已有覆盖的完整性 UNKNOWN。 |

重命名方面，名称派生 ID 与 `cf.file` 可分别变化；上述代码没有建立统一的、经验证的身份重命名协议。文件复制、跨存档复制与恢复是否保留同一人物的语义亦 UNKNOWN；不假定路径、inode 或内容摘要构成持久身份。现有 schema 10 和 9→10 的局限见安全审计 §现有 schema；未来 9/10→11 自动迁移及完整备份是已决定目标，不是现有能力。

## 2. 两种 B 兼容候选（均未批准为实现）

比较中的检测均以完整枚举、受控写者、可解析且未被同步伪造的证据为前提；任何前提不成立输出 UNKNOWN 并拒绝。二者都需要 sidecar 自身版本、角色绑定信息及操作版本，不将哈希称为认证。

* **P：存档内登记表 + 既有定位符与快照指纹。** 一份版本化登记表记录一对一角色路径、现有 ID 和 sidecar；入籍时检查全部对象并记录前像摘要。路径和 ID 是可变定位符，摘要仅用于检测与已知前像的变化。无须在人工 Markdown 内插入新字段，但没有独立于登记表的角色身份锚：手动同时替换角色和登记表或完整复制旧集合不能区分历史。
* **Q：角色承载随机身份令牌 + sidecar 双边绑定。** 受控入籍时向角色承载体和 sidecar 分别写同一高熵非秘密令牌、版本和绑定；仍需枚举校验令牌在所声明的存档作用域内唯一。旧 Markdown 是否可无损添加令牌、存档身份如何表示、随机源、令牌生命周期及克隆分叉协议均待批准/验证。令牌不是密钥；复制两边会复制令牌，不能鉴别拥有者或克隆意图。

| 场景 | P 可检测 / 不可保证 | Q 可检测 / 不可保证 | 最坏后果及决策或验证 |
|---|---|---|---|
| 旧角色、仅 Markdown、dirty/未知字段 | 唯一映射和快照不一致可检测；首次关联无法证明历史身份 | 重复/缺失令牌可检测；无损写入及初始关联正确性未知 | 误入籍污染历史；需所有者确认初始信任/人确认是否足够，试验保留原字节。 |
| 名称、ID、文件重命名 | 旧定位失配可检测；协作重命名需先后映射并重验 | 令牌可随受控重命名保持；旧版改写可能丢令牌 | 丢失关联或把历史赋给另一人；对 ID、party、进度引用改名的授权和完整更新另决，未知拒绝。 |
| 同存档复制角色及复制 sidecar | 路径/ID 或登记碰撞可发现；完整更换定位及登记可能伪装 | 令牌重复可发现；复制后重新生成或人为同步全部字段不能证明关系 | 同一选择被应用两次或给错角色；禁止自动分叉/去重，分叉语义需所有者决定。 |
| 跨存档完整副本、恢复、回滚或重放 | 若保存了同一登记表，两个副本不可仅凭内部数据判别；前像不符可检测 | 两边令牌一起复制时相同；独立存档不可能只靠内部扫描识别彼此 | 把旧历史作为新历史或错误恢复；作用域、克隆保留/分叉、回滚代际与外部可信锚是否需要均待决定；不得声称全局唯一。 |
| 孤儿、缺失、错位置、错绑、重放 | 登记缺对应对象、多重映射或快照偏差可发现；协调替换全部文件不可发现 | 令牌缺失、不同、重复可发现；匹配令牌不证明内容正当或新鲜 | 覆盖玩家历史/给错人升级；缺 sidecar 非空历史，身份不明停止，绝不按名字自动认领。 |
| 前后手改、旧程序或外部编辑器 | 已记录字段/摘要变化可发现，但检查之后再写仍有竞态；合法变更也会触发冲突 | 令牌与前像变化可发现；编辑器可删、复制或伪造令牌 | 覆盖手改；操作前后重验可缩小非协作竞态而不消除，冲突不自动重基或覆盖。 |
| 不完整枚举、权限错误、无效条目 | 无完整清单则无法证明唯一；必须失败 | 同左；不能仅扫带令牌的文件 | 漏掉重复/孤儿；枚举范围、文件系统、链接与权限需跨平台验证，不能当空目录。 |

两方案的 checksum 只能对比某个已知字节快照：不认证作者、身份、意图、真实性或新鲜度；攻击者可同步改所有文件，完整旧备份也可重放。人确认也不是密码学证明。恶意或不受控写者威胁范围、外部可信锚、全局身份、冲突人工处置及何时允许入籍/分叉，均须 Owner 决定；在决定和验证以前不选 P 或 Q。最坏是错误角色属性、XP、选择或资源被改变，真实历史或后续手改/日志被覆盖。

## 3. 共同候选契约：必须全部满足才可提交

这是可供审查的**必要条件**而非已批准具体协议；任一不可判定则只报告并停止，不能将停止升级为绕过选择的授权。

1. **作用域与入籍**：先明确存档身份边界、字符身份生命周期和适用的角色集合（包括 Characters、NPCs、结构化 sheet、sidecar、party/进度引用和未知相关路径）；对每个参与对象记录来源及版本。缺少可靠身份来源的旧对象标 UNKNOWN；不能由可见名称、文件名或现有 ID 单独入籍。首次关联及历史补录需要经批准的显式流程；不能把历史未知变为无记录。
2. **完整发现与唯一性**：枚举所有已定义范围，不丢失目录打开、条目读取、解析、权限、路径规范化、重复以及特殊文件错误；未决定的目录/文件类型按 UNKNOWN 停止，不视为空。识别跨目录/大小写/ID 与名称交叉冲突；以候选机制定义的身份和所有可引用的别名做一对一检查，扫描结构化孤儿与 sidecar 孤儿。一个角色只能对应一个身份与一个适用 sidecar；一个 sidecar 只能归属一个已确认角色。重复、缺失、未来版本、未知字段无法安全解析、错绑、复用或冲突都拒绝。现有 `check::sheets`/`find` 不能直接充当此验证器。
3. **手改与错误**：验证 Markdown combat ID、结构化内部 ID、文件引用、登记/令牌、sidecar 和 party/进度之间的预期关系，不把任何单一字段视为权威证明。记录前像，检测到变化或无法判定时保持用户数据原样，展示脱敏的冲突类别、受影响相对路径、未写/可能已写阶段及人工下一步；不回显秘密或正文。不覆盖未知字段、注释、历史和玩家手改；无损转换不能证明时停止。解决冲突不是自动选第一个，也不是静默接受新基线。
4. **预览与提交**：预览只读，绑定完整清单、身份映射、角色/party/进度、规则与授权、遭遇及有关状态的可验证快照；持有经未来审查的共享协作锁后重新发现、逐项校验并比较。新增、删除、变化、扫描失败或无法证明完整时拒绝，重新预览；非协作检查/写入间仍有 TOCTOU。活动遭遇仅预览，损坏、歧义或无法可靠判断也不提交。
5. **D、备份和恢复**：写入前取得相关协作锁、验证完整备份，持久记录唯一操作 ID、阶段、身份、完整前像和候选；完整候选树先构建验证，再逐文件复核前像并发布，空间不足、过期或校验失败停止，不能原位降级或声称多文件原子性。每步及日志/完整性按批准的阶段协议记录；失败保留备份和阶段记录。恢复前保护当时当前内容，由人明确选择；后续手改、追加日志、记录冲突或身份不明时不得自动覆盖或重放。备份/持久同步、阶段细节和平台语义尚未证明，见恢复选项 §3–4。
6. **写者边界**：所有相关新版本协作写者须纳入锁域，具体清单、顺序、生命周期和跨平台行为待设计验证；旧二进制、外部编辑器不受约束，逐入口审计并告知迁移后停止旧版写入。#264 根因 UNKNOWN；不能将现有 checkpoint 锁或成功测试作为安全证明。

## 5. 后续顺序与决策门

1. Master 和独立 Reviewer 对照本文件静态路径与测试，Owner 决定身份作用域、初始关联、重命名与克隆/分叉/恢复语义、可信威胁边界与冲突解决；重大安全或迁移选择不由执行者默认决定。相应活章程和书面设计按治理流程更新。无法达到 B 的可靠身份条件则停止，不擅自改选 A 或弱化约束。
2. **建议首个独立垂直任务**：在批准语义之后，仅用隔离合成 fixture 实现只读完整发现与身份关系诊断，提供结构化成功/歧义/UNKNOWN、重复及不完整枚举测试；不写 sidecar、角色、存档 schema、party 或进度，不执行迁移或升级。可独立证明“该测试输入下拒绝不明”，不能证明全平台或真实数据安全。若平台枚举/链接边界不能满足则阻塞并报告。
3. 依赖前项 VERIFIED、具体身份授权与跨平台文件系统调查，再单独设计/验证协作锁域及 #264 风险、完整备份与元数据、操作阶段和 D 故障恢复；安全审查与故障注入不得以只读诊断替代。然后才可立项版本化 sidecar 的入籍与 9/10→11 自动迁移，实现必须保留未知历史和手改。
4. 在可靠迁移/恢复及遭遇发现门完成后，按已批准规则、四规则集与授权隔离切分预览、显式选择、提交和端到端任务；仅可靠派生数值，其他由 DM 手动。每任务有独立合成负向和集成证据。首阶段全部验收后暂停，不进入全量专长自动化。
