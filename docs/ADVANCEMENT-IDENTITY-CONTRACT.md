# 成长 sidecar：角色身份事实与候选契约

状态：仅设计，静态事实基线 `5394ea2379302f6d4df912e7c1bc315b4856d4f9`；没有实施、迁移或证明可靠身份。所有者已选择 [B/D 与恢复边界](https://github.com/ctrlshiftaltdel/TalkDND/issues/183#issuecomment-6788131462)以及 [Q 和四条配套规则](https://github.com/ctrlshiftaltdel/TalkDND/issues/183#issuecomment-6896073489)；[成长设计](superpowers/specs/2026-11-10-character-advancement-design.md)、[恢复选项](ADVANCEMENT-RECOVERY-OPTIONS.md) 和 [安全审计](ADVANCEMENT-SAFETY-AUDIT.md) 为依据。仅核查公开代码和测试，不读取真实存档、书或秘密。UNKNOWN 表示尚不能判定，不代表安全或不存在。

已选 Q：角色承载体与 sidecar 保存同一随机非秘密标识，缺失、不一致或同一存档内重复均停止。旧角色保留原数据和未知历史，首次关联由 DM 核对确认，不能无损处理则停止。删除后同名或同 ID 重建不得自动继承历史；确需认领时须 DM 明确确认，并走带备份与阶段记录的显式重绑。身份仅在同档唯一，完整复制存档可作为独立分支；同档重复停止，不自动合并或分叉。恢复须先保护当前内容并由人明确确认。共同复制角色与 sidecar 或整体重放旧备份无法凭内部标识检测，不得承诺检测；旧程序和外部编辑器不受协作锁约束。

Q 的随机标识用于检查同一存档内的角色归属，安全边界见本文下文。恢复、结构化角色卡无损写入、跨平台备份以及 #264 仍需各自的实现和证据。

### 仅有 Markdown 的旧角色卡

所有者批准 DM 核对后在原文件末尾追加一行 `<!-- talkdnd-identity: <标识> -->`。追加内容使用原文件最近一处换行的风格。旧文件末尾、BOM、正文和所有手改字节都逐字保留。

角色的成长记录使用 `advancement/<id>.yaml`，v1 身份字段为 `card`、`token` 和 `history: unknown`。局部匹配、错配、同档重复和遗留孤立记录需要人工核对。候选登记使用一次性随机值，两个文件的提交和回退都需要经过已有的备份与恢复协议。

DM 可以用 `talkdnd advancement identity-preview --json` 只读核对。预览仅报告定位路径、状态和可追加时的原文件摘要、追加字节数。它不生成登记、不输出现有标识或角色正文，不取得存档锁。一致性和可写性都标为未验证。主存档仍使用 schema 10。

### 已有结构化角色卡

所有者批准由结构化 YAML 承载身份。预览在保留原字节的情况下，尝试在末尾追加顶层 `talkdnd_identity` 字段，再重新读取整个文件并比较原有映射。注释、缩进和未知键保留。无法追加、追加后改变原值或同时在 Markdown 发现标记时，预览会标明需要核对。

结构化载体的成长记录在 v1 中额外使用 `carrier` 指向 `sheets/<id>.yaml`；`card` 仍指向关联的 Markdown。两处路径与标识均须匹配。

## 1. 现有身份路径：静态事实及边界

以下路径均相对仓库根。测试名为静态定位，不意味着为本文执行过或证明侧车安全。

| 路径 | 可定位事实 | 限制 |
|---|---|---|
| `tools/talkdnd/src/chargen.rs::slug`, `sheet_with`, `valid_id`；`lib.rs::chargen_cmd` | `sheet_with` 从名称生成 slug，写入 Markdown combat 块的 `id`；slug 去撇号、把其他分隔转连字符并小写，保留 Unicode 字母数字。`valid_id` 只接受首位小写 ASCII/数字、后续小写 ASCII/数字/连字符、最多 80 字节。建卡写 `Characters/<id>.md`，加 campaign party，再调用 `from_chargen`。 | slug 可碰撞；Unicode slug 可能未通过 ASCII 校验。格式合法不代表唯一、不可变、出处可信或人与角色身份相同；创建并非多文件事务。 |
| `charsheet.rs::from_chargen`, `member_for` | `from_chargen` 以刚写入的 Markdown 创建 fresh 数据；若同 ID 的 YAML 已存在则以旧 `CharFile` 为基础，更新新建卡快照，并保留或合并既有 feats、inventory 等游玩字段。随后 `party` 调用 `member_for`，按 `cf.id` 复用已有成员并调整生命和资源；没有成员时才新增。`rerunning_chargen_sheet_keeps_play_data` 是保留字段的既有测试入口。 | **静态路径推演，未实测**：删除 Markdown 而保留旧 YAML、party/进度后，以同 slug 重建，可能复用旧角色游玩数据、party 成员及按 ID 引用的进度。当前枚举只剩一个匹配也不能证明身份历史连续；未断言真实存档发生过此事。所选方向禁止自动继承，显式重绑协议仍待设计。 |
| `lib.rs::npc_cmd` 的 `NpcCmd::Sheet`；`charsheet.rs::controller_for` | 同伴另走独立路径：生成 ID 后对 `check::sheets` 的**首个大小写敏感精确 ID**匹配检查 controller，匹配为 player 时拒绝覆盖；否则写 `Characters/<id>.md` 并 `add_to_party`。此路径不调用 `from_chargen`。 | 这不是全局唯一性校验：首项之后的重复项未检查；`sheets` 会跳过枚举/读取/解析失败项，保护范围仅限发现结果。不得据此推断同伴走了结构化重建或可靠身份验证。 |
| `check.rs::sheets`, `find` | 先 Characters 后 NPCs，每目录路径排序；无法读取目录、目录项、文件或解析 combat 块时跳过；缺失非字符串 id/name 变空串。`find` 对 ID **或**名称大小写不敏感的精确匹配使用第一个 `.find`；仅无精确匹配时才要求名称前缀唯一。 | 重复 ID、同名、一个 ID 等于另一名称时第一个精确项胜出；它不是唯一性检查。返回列表不保证枚举完整；不存在匹配不能证明不存在角色。大小写折叠与文件系统大小写规则不是同一东西。 |
| `charsheet.rs::path`, `load`, `parse_char_file`, `store`, `commit`, `markdown_path` | `load` 先发现/选择 Markdown，以其 ID 找 `sheets/<id>.yaml`；没有文件则从 Markdown `migrate` 到内存；有文件则解析，并在特定标记存在时吸收所选 Markdown 的 combat 块和尾部。`parse_char_file` 检查版本和 controller，所示路径未核对内部 ID 与发现 ID/路径一致；`store` 校验内部 ID 格式后按内部 ID 写。`commit` 依次存 YAML、party、按 `cf.file` 写 Markdown；`markdown_path` 检查相对路径组成。 | 一个合法 ID 可以指向另一个结构化文件，读入值和写出位置可能不同；`file` 路径合法不等于同一角色或 symlink 安全性已证明。写入次序非跨文件原子。不可据此声称任意真实存档有错绑。 |
| `charsheet.rs::migrate`, `migrate.rs::detect`, `migrate_sheets` | 旧 Markdown 的 combat ID/name、相对路径和主体进入结构化角色；无 meta 时 `detect` 根据 `check::sheets` 和相应 YAML 是否存在推断旧 schema。`migrate_sheets` 发现同 ID 的 YAML 就跳过。 | 枚举跳过的条目不会参与判断；同 ID 文件存在也不能证明对应角色。自动创建 sidecar 或把空历史当没有选择均不可推断。 |
| `migrate.rs::plan_companions`, `move_companions` | 旧 schema 向 6 迁移时，计划依据 sheet 的 `file`、combat side、campaign party 或 party state 等判定同伴，将 `NPCs/` 的相应文件移至 `Characters/`；目标冲突时分配空闲名称并警告。关联 sheet 存在时以文本编辑更新 `file: NPCs/...` 为新路径，其他 sheet 补 controller；`v5_companions_move_to_characters_and_story_npcs_stay` 是现有测试入口。 | 这是既有路径迁移，不是统一的身份重命名或绑定协议；计划阶段会跳过部分读取/枚举失败项，不能据此证明发现完整、身份唯一或全局引用已协调。移动和 sheet 更新分步执行，不能假设跨文件原子。 |
| `lib.rs::add_to_party`, `start.rs::party_ids`, `combat-sim/src/party.rs::PartyState`, `progress.rs::recipients`, `xp_add`, `level_up`, `purse_key` | campaign party 是 ID 列表，建卡添加时按字符串精确去重；party state 的 `members` 按 creature ID 作键。进度、XP/钱袋用 ID；显式目标经 `find`，`all/party` 从 campaign 列表取 ID；`level_up` 经发现角色及其 ID 读进度并决定结构化/Markdown 写路径。`party_ids` 无法读取或找不到时返回空。 | 引用是可用键，不是持久人物身份；重复或改 ID 可能共用或悬空进度、party。不能根据单个匹配自动重绑或移动历史。 |
| `charsheet.rs::rerunning_chargen_sheet_keeps_play_data`, `commit_rejects_sheet_paths_outside_the_save`；`tests/spells.rs::migration_skips_dirty_sheets_in_both_shapes`, `migration_without_integrity_manifest_keeps_every_sheet_byte_identical` | 现有合成测试分别检查重建保留指定游玩字段、拒绝 `../` 路径，以及法术迁移 dirty sheet 保护。 | 这些测试不证明全目录唯一性、身份绑定、外部写者、克隆或 sidecar 恢复。当前已有覆盖的完整性 UNKNOWN。 |

重命名方面，名称派生 ID 与 `cf.file` 可分别变化；上述代码没有建立统一的、经验证的身份重命名协议。完整存档副本可作独立分支，但内部标识不能证明同一人物或副本的新旧；具体克隆及恢复协议仍 UNKNOWN。不假定路径、inode 或内容摘要构成持久身份。现有 schema 10 和 9→10 的局限见安全审计 §现有 schema；未来 9/10→11 自动迁移及完整备份是已决定目标，不是现有能力。

## 2. B 兼容方案历史比较（已选 Q，均未实施）

比较中的检测均以完整枚举、受控写者、可解析且未被同步伪造的证据为前提；任何前提不成立输出 UNKNOWN 并拒绝。二者都需要 sidecar 自身版本、角色绑定信息及操作版本，不将哈希称为认证。

* **P：存档内登记表 + 既有定位符与快照指纹。** 一份版本化登记表记录一对一角色路径、现有 ID 和 sidecar；入籍时检查全部对象并记录前像摘要。路径和 ID 是可变定位符，摘要仅用于检测与已知前像的变化。无须在人工 Markdown 内插入新字段，但没有独立于登记表的角色身份锚：手动同时替换角色和登记表或完整复制旧集合不能区分历史。
* **Q（已选方向）：角色承载随机身份令牌 + sidecar 双边绑定。** 受控入籍时向角色承载体和 sidecar 分别写同一随机非秘密令牌；仍需枚举校验令牌在同一存档内唯一。旧 Markdown 是否可无损添加令牌、随机源、令牌生命周期及克隆分叉协议均待设计和验证。令牌不是密钥；复制两边会复制令牌，不能鉴别拥有者或克隆意图。

| 场景 | P 可检测 / 不可保证 | Q 可检测 / 不可保证 | 最坏后果及决策或验证 |
|---|---|---|---|
| 旧角色、仅 Markdown、dirty/未知字段 | 唯一映射和快照不一致可检测；首次关联无法证明历史身份 | 重复/缺失令牌可检测；无损写入及初始关联正确性未知 | 误入籍污染历史；首次关联须 DM 确认，验证保留原数据，无法无损处理停止。 |
| 名称、ID、文件重命名 | 旧定位失配可检测；协作重命名需先后映射并重验 | 令牌可随受控重命名保持；旧版改写可能丢令牌 | 丢失关联或把历史赋给另一人；对 ID、party、进度引用改名的授权和完整更新另决，未知拒绝。 |
| 同存档复制角色及复制 sidecar | 路径/ID 或登记碰撞可发现；完整更换定位及登记可能伪装 | 令牌重复可发现；复制后重新生成或人为同步全部字段不能证明关系 | 同一选择被应用两次或给错角色；同档重复停止，禁止自动分叉/去重。 |
| 跨存档完整副本、恢复、回滚或重放 | 若保存了同一登记表，两个副本不可仅凭内部数据判别；前像不符可检测 | 两边令牌一起复制时相同；独立存档不可能只靠内部扫描识别彼此 | 完整副本可为独立分支；回滚协议与外部可信锚是否需要仍待设计，不得声称全局唯一或检测整体重放。 |
| 孤儿、缺失、错位置、错绑、重放 | 登记缺对应对象、多重映射或快照偏差可发现；协调替换全部文件不可发现 | 令牌缺失、不同、重复可发现；匹配令牌不证明内容正当或新鲜 | 覆盖玩家历史/给错人升级；缺 sidecar 非空历史，身份不明停止，绝不按名字自动认领。 |
| 前后手改、旧程序或外部编辑器 | 已记录字段/摘要变化可发现，但检查之后再写仍有竞态；合法变更也会触发冲突 | 令牌与前像变化可发现；编辑器可删、复制或伪造令牌 | 覆盖手改；操作前后重验可缩小非协作竞态而不消除，冲突不自动重基或覆盖。 |
| 不完整枚举、权限错误、无效条目 | 无完整清单则无法证明唯一；必须失败 | 同左；不能仅扫带令牌的文件 | 漏掉重复/孤儿；枚举范围、文件系统、链接与权限需跨平台验证，不能当空目录。 |

上表保留原候选分析供历史对照，Q 已选，P 未选；可检测性仅为前提满足时的设计分析而非实测。checksum 只能对比某个已知字节快照：不认证作者、身份、意图、真实性或新鲜度；攻击者可同步改所有文件，完整旧备份也可重放。人确认也不是密码学证明。恶意或不受控写者威胁范围、外部可信锚和具体冲突处置仍须设计与必要决策。最坏是错误角色属性、XP、选择或资源被改变，真实历史或后续手改/日志被覆盖。

## 3. 共同候选契约：必须全部满足才可提交

这是可供审查的**必要条件**而非已批准具体协议；任一不可判定则只报告并停止，不能将停止升级为绕过选择的授权。

1. **作用域与入籍**：身份只在同档唯一；具体生命周期和适用的角色集合（包括 Characters、NPCs、结构化 sheet、sidecar、party/进度引用和未知相关路径）仍须明确；对每个参与对象记录来源及版本。缺少可靠身份来源的旧对象标 UNKNOWN；不能由可见名称、文件名、现有 ID 或摘要自动入籍。首次关联须 DM 确认；历史补录使用显式流程，不能把历史未知变为无记录。
2. **完整发现与唯一性**：枚举所有已定义范围，不丢失目录打开、条目读取、解析、权限、路径规范化、重复以及特殊文件错误；未决定的目录/文件类型按 UNKNOWN 停止，不视为空。识别跨目录/大小写/ID 与名称交叉冲突；以候选机制定义的身份和所有可引用的别名做一对一检查，扫描结构化孤儿与 sidecar 孤儿。一个角色只能对应一个身份与一个适用 sidecar；一个 sidecar 只能归属一个已确认角色。重复、缺失、未来版本、未知字段无法安全解析、错绑、复用或冲突都拒绝。现有 `check::sheets`/`find` 不能直接充当此验证器。
3. **手改与错误**：验证 Markdown combat ID、结构化内部 ID、文件引用、登记/令牌、sidecar 和 party/进度之间的预期关系，不把任何单一字段视为权威证明。记录前像，检测到变化或无法判定时保持用户数据原样，展示脱敏的冲突类别、受影响相对路径、未写/可能已写阶段及人工下一步；不回显秘密或正文。不覆盖未知字段、注释、历史和玩家手改；无损转换不能证明时停止。解决冲突不是自动选第一个，也不是静默接受新基线。
4. **预览与提交**：预览只读，绑定完整清单、身份映射、角色/party/进度、规则与授权、遭遇及有关状态的可验证快照；持有经未来审查的共享协作锁后重新发现、逐项校验并比较。新增、删除、变化、扫描失败或无法证明完整时拒绝，重新预览；非协作检查/写入间仍有 TOCTOU。活动遭遇仅预览，损坏、歧义或无法可靠判断也不提交。
5. **D、备份和恢复**：写入前取得相关协作锁、验证完整备份，持久记录唯一操作 ID、阶段、身份、完整前像和候选；完整候选树先构建验证，再逐文件复核前像并发布，空间不足、过期或校验失败停止，不能原位降级或声称多文件原子性。每步及日志/完整性按批准的阶段协议记录；失败保留备份和阶段记录。恢复前保护当时当前内容，由人明确选择；后续手改、追加日志、记录冲突或身份不明时不得自动覆盖或重放。备份/持久同步、阶段细节和平台语义尚未证明，见恢复选项 §3–4。
6. **写者边界**：所有相关新版本协作写者须纳入锁域，具体清单、顺序、生命周期和跨平台行为待设计验证；旧二进制、外部编辑器不受约束，逐入口审计并告知迁移后停止旧版写入。#264 根因 UNKNOWN；不能将现有 checkpoint 锁或成功测试作为安全证明。

## 4. 合成测试设计 — 全部 NOT_RUN

以下仅为未来合成 fixture 验收，不是本任务 AC 证据，也不是当前执行结果。失败路径逐一比较目标、sidecar、party、进度、日志与未知文件的原字节；对于已开始逐文件发布的故障，核对保留备份/阶段记录并要求显式恢复，而非声称全部不变。

| 场景 | 未来断言 |
|---|---|
| 完整发现：缺目录、拒绝访问、迭代出错、无效 YAML、不可读或未知类型 | 无法证明枚举完整时拒绝；不把跳过当空；输出类别而不泄露内容。 |
| 重复 ID、大小写冲突、同名及名称碰撞另一个 ID、跨 Characters/NPCs | 不使用首个精确匹配；无更改；报告歧义。 |

| 受控改名、同档复制、整档克隆、跨档侧车复制及旧快照重放 | 完整存档克隆可作为独立分支；同档重复停止。对无法从相同内部字节区分的新旧或人物关系标 UNKNOWN，依赖该判定的关联或恢复不猜测、不继续；不虚构检测能力。具体协议仍待设计。 |

## 6. #327 决策稿 — Q 的写入契约候选

本节由 [#327](https://github.com/ctrlshiftaltdel/TalkDND/issues/327) 暂拟，待所有者决定。方向 Q、按载体无损追加和显式恢复沿用章程既有决定。当前 `advancement_identity.rs` 仅预览；以下写入、改名、重绑及恢复断言是 [#330](https://github.com/ctrlshiftaltdel/TalkDND/issues/330) 及后续实现的验收输入。

### 绑定格式与生成

推荐延续只读预览已识别的身份格式。仅有 Markdown 的卡使用一行 `<!-- talkdnd-identity: <token> -->`；存在结构化卡时仅允许 `sheets/<id>.yaml` 顶层 `talkdnd_identity`，其值是带引号的标识字符串。绑定目标为 `advancement/<id>.yaml`，每个可成长角色登记一份，载体与 sidecar 的标识逐字相等。`id`、`card` 与 `carrier` 仅用于定位和校验关系；显示名、摘要、路径、文件 ID 和锁的 `save_id` 均不作为人物标识。

| `advancement/<id>.yaml` 的 v1 字段 | 候选约束 |
| --- | --- |
| `version` | 整数 `1`，读写均按该版本验证完整结构。严格拒绝未知版本、未知键、重复键、缺失字段和错误类型。 |
| `card` | 该角色实际的 `Characters/` 下 Markdown 路径，以存档为根的规范相对字符串。 |
| `carrier` | Markdown 载体时省略。结构化卡时必填，值是经完全枚举并唯一绑定的 `sheets/<id>.yaml`。 |
| `token` | 128 位操作系统随机值，以 32 位小写十六进制字符串编码。保留全零给只读形状探测，禁止持久化。 |
| `history` | 首次入籍为 `unknown`。严格的身份 v1 只接受该值。未来选择记录需明文定义版本分派和旧版行为，保持旧选择未知，空的新增记录只表示自该边界起尚无新记录。 |

写入候选在 SAVE 锁内逐项枚举并验证 `Characters/`、`NPCs/`、`sheets/`、`advancement/` 和相关 party、进度引用。先核对卡的 combat ID、sheet 的内部 ID 和 `file`、sidecar 文件名及其路径字段。目录项读取或解析错误、重解析点、符号链接、硬链接、大小写归一冲突和无法证实的文件归属均须按受支持平台的准入规则拒绝。允许尚未入籍的角色仅在 `schema` 9/10 下缺两侧标识，并进入人工初次核对。schema 11 遇到缺单侧或双侧标识时拒绝。读取全部记录后计算唯一性，包含未配对记录和本次候选，孤立记录阻止普通写入。以成对相等作为一份绑定计数，即使同一角色的两个载体放了相同标识，也按载体冲突拒绝。

迁移开放前逐项审计新建、建卡重跑、结构化卡重存、Markdown 输出、命令行升级和恢复等协作写者。保存既有卡须留住标识和原有归属，遇到无法保留的重序列化或载体转换则停止。新建角色的入籍路径、首次创建 `advancement/` 目录及前像缺失与空文件的区分均须实现和取证，才能开放 schema 11 写入。现有只读形状探测仍可用全零计算追加长度，登记和写入复核必须拒绝磁盘上出现的全零值。

推荐复用 `combat-sim` 已锁定的 `rand` 0.9.5，在实现任务中从 `OsRng` 通过 `TryRngCore::try_fill_bytes` 取得 16 字节，并向调用方返回错误。`tools/combat-sim/src/dice.rs` 中 `OsDiceRng` 的 `RngCore::fill_bytes` 把该 API 的错误转换成 panic，保持原有骰路径即可。只在取得 SAVE、校验前像且确认登记后为候选生成标识，不在日志或输出中回显。每个标识最多尝试生成 8 次，每次排除全零和当前存档中已有或已保留的标识。熵失败或耗尽重试次数时停止，用户数据原样保留。合成验收注入全零、碰撞、连续碰撞和熵失败，生产路径不接受注入值。时间、名称、路径及锁 ID 的哈希不满足 Q 的随机约束。此方案复用已有依赖，其他依赖方案继续单独审批。

### 合成样例 — 纸面走查

下表用转义后的 `\n`、`\r\n` 表示换行，`T` 表示合成的非零 32 位小写十六进制字符串。每个成功候选均断言原文件是新文件的逐字节前缀，并按文件现有最后一处换行选择风格；没有换行时使用 LF。带 UTF-8 BOM 的文件也保留 BOM。写入前重新读回候选并核对绑定；解析失败、已存在标记或无法确认顶层附加位置时停止，禁止重序列化原文件。

| 输入 | 候选与断言 |
| --- | --- |
| Markdown 原字节为 `# Sample\r\nDM note`，没有末尾换行。 | 追加 `\r\n\r\n<!-- talkdnd-identity: T -->\r\n`。正文与既有字节保持原样，追加标记只出现一次且为独立注释。若仍处于未闭合围栏、HTML 块等使附加标记语义不明的位置，则拒绝。 |
| YAML 原字节为 `id: sample\nfile: Characters/sample.md\ncustom: [4, 8] # hand note`。 | 追加 `\ntalkdnd_identity: "T"\n`。以项目实际的 YAML 解析器重读。移除新增键后，顶层 `id`、`file` 和未知键 `custom` 的值与原映射逐项相等；注释仍在原字节前缀中。 |
| YAML 多文档、显式文档末尾、非映射、重复键、同名保留键或附加后改变原值的末尾标量。 | 出现已存标识时按绑定或冲突处理，其余不能确认无损时拒绝；候选不得改写正文、原映射或文档形状。 |
| Markdown 与 YAML 都有标记，或 Markdown 出现两个标记、近似保留标记或不合法的标识。 | 拒绝整个关联；即使两个标识相等也不选主载体。 |

### 生命周期与拒绝矩阵

所有写入只有受支持平台的准入、完整备份、SAVE、D 阶段协议和遭遇门齐备后才可启用。预览一律只读，现有 `consistency: unverified` 与 `write_capability: unverified` 保持。规划里可以显示临时的关联候选，提交需要核对 DM 确认、完整枚举、以前像摘要绑定的旧值、运行时规则集和授权、可核验的锁/存档和遭遇状态。锁内重检前像，变化一律停止重做预览。核查失败须指出冲突类别与安全的相对定位，并区分尚未发布与已部分发布。

| 操作或场景 | 推荐行为与验收断言 |
| --- | --- |
| 首次关联 schema 9/10，名单、引用一致且两个位置都未登记。 | DM 确认确切角色及历史未知；验证完整备份及前像后生成标识、写入无损候选。D 把角色载体、sidecar、主 schema 元数据及其它受影响目标纳入同一操作记录，完成后才报告配对成功。缺确认、视图过期、已有单侧标识或候选无法验证时原数据保持。 |
| 改显示名，ID、路径与绑定未变。 | 在普通受控路径更新名称，保持标识和 sidecar 历史，重验引用及同档歧义。物理路径或 ID 变化涉及队伍、进度及 sidecar 文件名引用迁移，仅在另获批准且具备经验证发布／恢复的受控移动流程后允许，当前失败关闭。手动改路径后不得借显示名自动认领。 |
| 删除卡后同名或同 ID 重建，留下旧 YAML、party、进度或 sidecar。 | 判为重新出现的未验证角色及待人工核对的旧身份，停止普通写入；无自动合并、分支、补标识或复用历史。全新角色入籍前也必须明确处理现存冲突。 |
| 显式重绑，候选为同 ID 的替代载体。 | DM 明确选择并登记旧 sidecar 当事目标、新卡的路径和前像、认领依据。必须唯一定位原记录，旧标记载体已不再是另一存活角色，目标无标识且无竞争记录，相关 YAML/party/进度引用均能重验。经完整备份与 D 后保留获确认的旧标识和历史，在新载体追加标记并更新同一 sidecar 的路径；阶段记录与前像/目标绑定。若旧载体仍在、目标已绑定、不能证明引用归属或必须移动／删除目标才能完成，停止并等待受控流程；本稿不批准文件删除。 |
| 同档复制角色或 sidecar，错绑、孤儿、未完成枚举。 | 删除重建后的孤儿只可由已批准的显式重绑／恢复处理；日常预览仅报告，写入拒绝。复制到同档导致标识重复即停止；文件名可变、被拷贝内容相等或只有一个可读项都不证明归属。 |
| 完整复制存档为独立分支。 | 角色身份的唯一性范围仍为单档，保留整档副本内成对标识。锁 v1 独立校验路径和文件身份，当前对移动／复制后的成长写入拒绝。允许副本作为独立身份域不授予锁接纳，也不重建或复用控制记录；启用副本写入需单独授权和验收。 |
| 回滚或继续一次已开始发布的操作。 | 先保护当下整树和工作证据，再由人选择依据哪个已验证操作继续或回滚。检查每项当前前像/目标和日志新旧。候选可部分发布，须依 D 的阶段记录识别；后续手改、日志冲突、身份不清或缺证据时停止。不得凭两侧标识相等自动重放，也不得把共同替换、成对跨档复制或整档旧快照重放宣称为可检测。 |
