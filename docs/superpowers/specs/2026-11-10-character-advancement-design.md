# 单职业成长与专长：设计

状态：所有者已批准书面设计，完成后可继续后续工作，无须再为常规设计或计划评审询问；这不是任务状态或已交付功能。范围及已确认意图见 Issue #256；该常规授权不批准尚未决定的 schema、迁移、安全、规则语义等重大事项的具体方案，也不授权合并 main。依项目决策门逐项处理重大未决事项；本任务本身不实施或创建实施任务。本文不复制规则书文字，也不使用真实角色、存档或私有内容。

## 1. 目标与边界

先支持单职业升级时由玩家选择属性提升或专长，选择纳入升级而非由程序自动选择。基础阶段记录选择、验证程序可判定的条件、计算明确可计算的属性变化；不能自动实现的效果明确交 DM 手动处理。已知不合法必须拒绝且不可由 DM 覆盖；未知前提允许 DM 显式确认并记录依据，标明未经程序验证。未识别专长可由 DM 显式登记名称和来源，标未验证、效果手动，但不能绕过任何已知不合法条件，包括资格、来源权限和重复限制。以上不等于批准具体规则表达或实现。

一档一版：2014/2024 与 SRD/FULL 的现有隔离、授权及解锁不变；SRD 不读取 FULL，FULL 缺少合格解锁包不得静默降级。手动登记不是加载、公开或授权受限内容的途径。禁止将玩家书籍、存档、DM 秘密及版权正文写入 Git、Issue、PR、提交或 CI；测试仅用合成数据。

非目标：多职业、自动选项、无条件强制全部效果、实现代码或迁移、修改规则数据、增依赖或权限、改变四规则集与解锁机制；也不声称全量专长可自动化。效果自动化是后续分批目标，不是本次交付。

## 3. 交互与验证契约（具体未决事项见第 5 节，不指定命令或数据格式）

1. **预览**：读取当前存档规则集、职业、等级、手改状态、授权内容与已有选择；展示升级等级、可用机会及其来源、候选、潜在属性和派生变化、未知项和手动效果。预览不写入、不掷持久化骰、不暗示所有候选均合法。缺少可信职业/等级/资格来源时停止并解释，不能猜测。
2. **选择**：玩家显式选择本次机会；不自动替选。DM 可以在无法识别时输入名称和来源，并声明手动处理；不能用别名、大小写或手动入口规避已知非法。不能确定身份是否与已知条目相同时应暂停并要求消歧，不能以“未知”覆盖已知约束。
3. **校验**：对每个条件返回 `满足 / 不满足 / 未知` 及依据、来源与规则版本；已知不满足优先于任何未知和 DM 确认并拒绝。未知仅在 DM 明确确认、填写可审计依据时可继续，显示“未经程序验证”，不得转成已验证。对未识别项只允许在可独立判断的机会、来源授权、重复等已知条件通过后登记；无法可靠判断的条件须标未知，不假装通过。输入格式错误、越界、身份歧义、错误规则集、未授权内容和可判定的重复拒绝，不写入。
4. **提交**：再次比对预览时的角色与内容版本，若被手改或并发改变则拒绝、重新预览；按已批准的事务/恢复方案提交一次选择及可计算属性变化，与升级和现有 HP、熟练、法术、party 同步协调。不可覆盖手动值或静默重新生成；无法可靠计算的派生项提示人工处理，不假装更新。成功后展示前后差异、条件逐项状态、来源、确认依据、未实现效果和需要的手动操作。
5. **审计与重复**：记录一次机会与选择的关联、版本/来源、验证结果及必要 DM 确认依据，避免重复应用；审计内容留在本机，输出不得包含书籍正文或秘密。失败必须说明已写/未写阶段、可恢复位置和后续动作；重复请求或恢复重试不重复增加属性、XP、资源或日志。如何标识机会、处理可重复专长和历史无记录数据是第 5 节待决项。

上面是行为目标而非宣称现有程序已满足。具体属性上限、前提、来源及版间差异须来自获授权的版本数据，不能依据名称硬编码或凭记忆补规则。属性改变涉及 HP、攻击、豁免、技能、施法 DC、资源与当前遭遇：哪些安全自动重算、哪些保留人工改动须先确认；不能把旧值全部覆盖。

## 4. 兼容、失败与验证方案

旧 schema 10、旧 Markdown、结构化表、手改属性/特性及历史未记录选择都要保持可读且不静默改写；缺失记录表示未知而不是没有专长。更高版本继续失败关闭。既有迁移/备份是参考而非已批准的新迁移；导入或补录须预览、保留原数据并经人确认。部分写入尤其危险：角色 YAML、Markdown、party state、进度、日志、完整性清单可能不同步；现有升级先写角色、后写里程碑和日志，不能假设失败即无变化。

候选方案：A 在提交前建立可恢复整档备份、暂存目标、校验并按可诊断阶段提交，失败明确报告与提供恢复路径；B 用持久事务记录和幂等恢复处理每阶段。A 较易复用现有备份但仍需处理崩溃窗口；B 恢复更细但引入持久状态和复杂度。两者均须证明锁顺序、磁盘不足/中断、完整性重建和恢复后不重复提交；选型、schema 与权限影响待所有者决定，不在此定案。备份失败必须停止；恢复本身也需防止覆盖后续手改和误丢日志。

后续实现验收须用合成 fixture：

- 单元：两版不同机会与上限、选择互斥、合法/非法/未知前提、已知非法加未知仍拒绝、DM 确认依据为空拒绝、手动身份冲突与重复、数值越界；验证不泄露文本。
- 迁移/兼容：schema 10、缺失结构化表、旧 Markdown、dirty sheet、手动调整、未知未来 schema；迁移预览不写，备份失败不写，重试幂等，逐字保留无关手改；变更 schema 前须批准自动迁移及版本策略。
- 故障注入：各个角色/party/进度/日志/完整性写入前后、磁盘满、进程中断、并发和过期预览；核对准确阶段、备份可恢复、重试不重复、无静默覆盖。不能以单文件原子写证明多文件原子。
- 集成：四规则集分别检查版别和解锁隔离（FULL 缺失/锁定/错误版拒绝，SRD 不读取 FULL）；从升级预览到选择、审计、角色可见结果、法术和战斗读取的合成端到端；保留现有法术列表、已消耗资源和遭遇状态，未实现效果必须显式手动。回归既有升级与完整性检查。

## 5. 必须先决策的问题与选项

1. **schema/存储**：沿用兼容字段或新 sidecar；或提升主 schema 并自动迁移。比较旧二进制失败关闭、版本检测、手改与回滚；任何 schema 变更须自动迁移并升次/主版本。
2. **历史与身份**：仅保留历史未知并手动补录，或提供预览式导入；如何区分可重复选择、来源同名和历史机会，不能猜测。
3. **写入/恢复**：采用第 4 节 A 或 B，确定锁、失败点、备份保留与完整性策略；最坏为角色、XP、party 不一致或覆盖手改。Master 与独立 Reviewer 在未来实现 PR 检查故障注入证据与备份恢复，不由本文批准。
4. **规则语义**：各版机会、属性上限、前提、重复、先后顺序和升级时体质变化对 HP 的影响，选择采用可授权结构化数据或先保留 DM 裁定；明确拒绝/未知的边界与确认权限。不能把提示文案当规则权威。
5. **内容接入与权限**：复用现有 Registry 或增补适配层，核实授权包来源、同名覆盖与手动登记边界；依赖、权限或授权变化须另请批准。未决项不阻止常规后续工作，但阻止未经具体批准的对应实施决定。
