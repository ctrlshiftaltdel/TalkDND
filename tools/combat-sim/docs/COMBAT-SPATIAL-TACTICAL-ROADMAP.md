# 战斗空间模型与战术 AI：实现路线图

状态：Track S 提案；P0 已由 TASK-0085（#169）于 2026-10-27 冻结，P1 起以 `SPATIAL-RULES-MATRIX.md` 与 `SPATIAL-CONTRACT-v1.md` 为准。本文是 #168 的空间 / 战术 AI 路线图，不再是顶层总路线；顶层路线见 TASK-0097（#183），Track S 对应 v1.8 / v1.9 / v1.12。
适用范围：TalkDND / tools/combat-sim；同时支持 2014 与 2024 两套规则，但单个存档只能选择一个 ruleset。
关联现状：DESIGN-v2.md、SPEC-v2.md、src/space.rs、src/state.rs、src/ai.rs、SPATIAL-RULES-MATRIX.md、SPATIAL-CONTRACT-v1.md。
维护原则：本文定义实施顺序、接口边界、验收与回退方式，不替代规则原书，也不收录受版权保护的规则正文。本文与冻结契约冲突时，以 #169 的两份文档为准。

## 1. 目标与完成定义

将 combat-sim 从“区域图 + 简化 2D 格子 + 启发式选择”逐步演进为共享同一规则核心的空间与战术决策系统，具备：

1. **一致的空间语义**：距离、射程、触及、占位、阻挡、掩护、视线、范围效果、移动代价和借机威胁都由统一查询 API 计算，避免 CLI、引擎和 AI 各自实现不同判定。
2. **尺寸与体积感知**：大型以上生物不再仅由中心点表示；区分战斗占位、移动碰撞体、目标体积与地形体积。支持明确配置的高度、飞行与垂直互动。
3. **可组合的路径规划**：对所有可达位置使用 Dijkstra，对单目标寻路使用 A*；路径边携带成本和动作触发信息；执行路径仍由规则引擎逐步裁定。
4. **可控的朝向扩展**：空间状态可以保存面向方向，但两个默认 profile 都不添加正面/侧面/背面命中修正、包抄或转向成本；2014 的 Facing 是官方可选规则，2024 没有对应可选规则。需要这些规则时必须显式启用独立的可配置战役扩展 profile。
5. **具备团队目标的战术 AI**：从“选择期望值高的攻击”扩展到任务/行为约束、候选动作生成、战术效用评估和有预算上限的概率搜索。
6. **旧存档兼容**：旧 Position、旧 encounter state JSON、旧规则数据和现有 CLI 行为有明确向后兼容路径；任何持久化改动都带有默认值、迁移与回归测试。
7. **可比较、可回退**：保留 legacy 2D 行为路径；用合成场景基准对新旧寻路与 AI 做质量、合法性、性能和可复现性比较。

完成不是“有 3D 坐标/能跑 A*”就算通过。每个阶段需满足本文件的验收条件；所有动作必须仍经过唯一规则结算核心。

## 2. 基于 2014 / 2024 PHB / DMG 的规则边界

本表区分三种来源：**规则基线**（以用户本地 2014 / 2024 PHB/DMG 中适用条目核对）、**数字模型约定**（为可计算性作出的实现选择）、**可选扩展**（不是默认 RAW）。

| 主题 | 规则基线 / 来源定位 | 引擎落实 | 不能混淆的边界 |
| --- | --- | --- | --- |
| 回合与移动 | PHB 战斗章：先攻、回合、移动速度、困难地形、移动经过其他生物 | 所有候选移动统一进入规则校验器；以每一步结算动作与触发 | 寻路算法不能绕过回合、速度与动作经济 |
| 5 尺格子 | 2014 PHB p.192；2014 DMG p.252（可选 5-10-5）；2024 PHB p.25 / SRD p.13 | 默认每格 5 尺；把对角规则写成显式 profile 并测试 | 5-10-5 只在 2014 显式 profile 启用；不能无条件用欧氏距离取代规则规定的格子计距 |
| 生物体型 | PHB 体型/占位表：Tiny、Small、Medium、Large、Huge、Gargantuan 的水平空间占用 | 将格子占位 footprint 与单点位置分离，查询占位/可通过空间 | 书中的空间占用不等于生物真实的碰撞几何，也不自动给出身体高度 |
| 距离、触及和射程 | PHB 战斗章的距离、触及、射程与近战攻击规则 | 分离 distance policy、range check、reach check、movement cost | 不能把寻路成本、战斗距离与触及简单共用一个数值 |
| 掩护与区域效果 | PHB 战斗章与规则词汇中的半掩护、四分之三掩护、完全掩护，以及圆锥/立方体/圆柱/扩散/线/球等效果形状 | 按攻击者/目标体积、障碍与效果几何统一求值；确定性计算视线/覆盖关系 | 不能只测试中心点；不同效果形状需使用自己的相交策略 |
| 飞行与坠落 | PHB 规则词汇中的飞行速度、悬停、特定状态下失去飞行支持和坠落结算 | FlightState、FlightMovement、FallResolver、VerticalInteraction 分层 | 规则触发条件与坠落伤害/落地状态必须来自 ruleset 数据/实现，不能由路径成本推导 |
| 朝向 / facing | 2014 DMG p.252（可选 Facing）；2024 PHB / DMG 未提供可作为通用默认规则的统一角色朝向/攻击弧规则 | 可以保存 Facing，并提供可插拔 policy | 2014 仅为官方可选、2024 无此可选规则；两个默认 profile 都不启用正面/侧面/背面命中修正、包抄加值或强制转向成本 |
| 战术与防御行为 | DMG 第 4 章 Monster Behavior / Reactive Tactics / Prepared Defenders：目标、动机、警报、增援、伏击、防御工事与预备应对 | AI profile 需表达目标、纪律、警戒、撤退、保护对象、协同与环境利用 | AI 不应退化成所有敌人都最大化期望伤害；不得读取它在场景中并不知道的 DM 秘密 |
| 2014 / 2024 分层 | TalkDND 项目章程：一个存档一个 ruleset，加载 common 后加载选定版本目录 | 几何查询接受 ruleset/profile 中明确的规则策略 | 不允许一个存档混用两套版本的规则语义 |

2014 DMG 印刷 p.252 提供两个官方可选规则：5-10-5 对角计距与 Facing（正面/侧面/背面）。两者默认关闭，只在 2014 的显式 optional profile 中启用；2024 没有对应的可选规则，默认 profile 同样关闭。它们都不是任一版本的默认 RAW。对应条目见 `SPATIAL-RULES-MATRIX.md` 的 S-03 与 F-01/F-02。

证据定位仅供研发查阅：2024 PHB 战斗章（印刷页约 24–29）、规则词汇表中 Creature Size / Flying / Falling / Areas of Effect 等条目；2024 DMG 第 2 章 Running Combat、第 4 章 Monster Behavior / Reactive Tactics / Prepared Defenders（印刷页约 116–118）。2014 侧使用 PHB p.192 与 DMG p.252。页码和适用条件应由执行者在本地正版书中复核。项目不得将扫描 PDF、整段原文、非 SRD 生物数据或冒险/DM 秘密提交到 Git、Issue、PR、CI 或公开日志。公开可分发内容继续以合规 SRD 为边界并保留必要署名。

## 3. 架构目标与边界

### 3.1 数据流

规则/内容数据 → encounter snapshot → Spatial Query Kernel → 规则合法性校验与状态转移 → AI 候选生成与评估 → CLI/日志输出。

- **规则引擎是唯一权威**：AI 只能产生候选动作，不得直接修改 CombatantState 或绕过引擎执行动作。
- **空间层只回答几何与通行问题**：移动预算、动作经济、借机攻击、陷阱触发、飞行失效和坠落伤害由规则结算层按正确顺序处理。
- **内容驱动而不是名称驱动**：不在 src 中硬编码具体怪物、法术、职业能力、状态或战役名称；规则差异使用通用 schema / profile 表达。
- **区域图继续存在**：Zones 是抽象空间图，Grid 是具象空间；两者实现共同 query contract，但不强迫 Zone 伪装成精确 3D 网格。
- **AI 采用可替换的规划器**：保留当前启发式作为 baseline/fallback；新增 UtilityPlanner 和有上限的 SearchPlanner，均消费相同候选动作和规则引擎。
- **无新依赖默认**：A*/Dijkstra、概率期望与有限深度搜索优先使用现有 Rust 能力；任何新增 crate 需事先获得项目所有者批准。

### 3.2 空间模型建议

类型名称与默认值以 TASK-0085 冻结的 `SPATIAL-CONTRACT-v1.md` 为准；以下只保留设计意图，不要求照抄草案。契约是加法式的：不改变 `Position` / `SceneMode` 现有变体或签名，P1 不改 `engine.rs` / `ai.rs` / `cli.rs`。

- **SpatialPose**：网格坐标 x/y 与高度 z（以整数英尺或经过规范化的 5 尺层级表达）、可选 Facing、运动模式；位置坐标不得使用浮点累积。
- **GridPosition3**：明确的离散坐标系和单位；z=0 对旧 2D 存档表示兼容。必须定义地图原点、向上轴、地图边界和超范围策略。
- **Footprint**：生物水平占位形状与尺寸。首版可用规则网格对齐的矩形/可配置格集合；不得把所有生物都当作占一格。契约已决定 v1 每个 5 尺格只放一个 token，Tiny 的四只同格规则记录但暂不实现。
- **CollisionVolume**：用于移动和穿越的空间实体；可由底面 footprint + 声明高度组成，数据缺失时使用明确的简化 profile，不得猜测精确生理尺寸。
- **TargetVolume**：用于攻击、视线、范围效果和掩护的目标体积。它可以与 CollisionVolume 不同，避免“能通过”被误当成“能被看见/能被命中”。
- **TerrainVolume**：障碍、墙、低矮掩体、天花板、悬崖、困难地形、危险格与触发器；属性分别表达可通过、可阻挡视线、影响掩护、产生移动代价与触发效果。
- **MovementProfile**：行走、攀爬、飞行、游泳、掘地等模式及速度/限制。能使用何种模式是规则问题；空间层只计算可行边及几何代价。
- **Facing**：离散 8 向或其他显式声明的方向；朝向记录与朝向规则分开。2014 DMG p.252 的 Facing 是官方可选规则，2024 没有对应可选规则；默认 profile 均关闭，只有显式 profile 才决定转向成本、前方弧、盲区、包抄等是否有意义。
- **SpatialRulesProfile**：定义网格对角计距、垂直移动成本、对角穿角、体积近似、射程距离度量、范围边界相交、朝向规则以及旧模式开关。所有默认值需写入契约并有测试。

### 3.3 必需查询 API

查询命名可调整，但语义必须独立、可测试，不允许一个 distance() 同时承担所有含义：

1. **can_occupy(pose, footprint, world)**：整块占位是否处于合法空间；检查边界、地形和其他生物。
2. **can_traverse(from, to, movement_profile, world)**：该移动模式能否通过完整移动边/扫掠体积；仅目的地空闲不够。
3. **movement_cost(edge, profile, rules)**：返回基础距离、困难地形/攀爬附加成本、所用移动模式与失败原因。
4. **reachable_positions(start, budget, profile, occupancy)**：返回成本表和可重建路径，使用 Dijkstra 或等价最短路算法。
5. **distance_between(a, b, policy)**：显式选择 grid range / vertical-aware / zone graph 距离策略；不得静默混用。
6. **can_reach(attacker_volume, target_volume, reach, policy)**：评估可用触及关系而非中心点间距。
7. **line_of_sight(observer_volume, target_volume, blockers)**：返回明确的阻挡依据和可见关系。
8. **cover_between(attacker_volume, target_volume, blockers)**：输出 none/half/three-quarters/total 或现有枚举可表达的值。
9. **area_intersection(effect_geometry, target_volume, origin, policy)**：返回被影响的目标/位置，统一支持范围形状。
10. **threatens_departure(observer, mover, from, to, rules)**：根据真实威胁范围和路径步骤判断借机攻击资格。

每个 query 应有明确单位、坐标约定、无效位置语义、边界语义与结果可复现性。诊断构建可返回命中/阻挡证据；正式路径可以使用较轻量结果。

## 4. 算法实现原则

### 4.1 距离与相交

- 对格子移动、射程距离、近战触及、效果半径、坠落垂直距离分别指定 metric，不能因为共享坐标系就共享算法。
- 对角计距默认每格 5 尺；2014 DMG p.252 的可选 5-10-5 只在 2014 显式 profile 启用，2024 没有此可选规则。
- 使用整数定点单位（推荐内部统一英尺整数，格点间距由 profile 决定），避免浮点比较和跨平台边界不一致。
- 线段/体积相交需定义端点是否包括、贴边是否算相交、对角线穿越角的判定顺序，以及多条视线采样的确定性。
- 视线、掩护和 AoE 首版采用有界、可解释、适用于离散战场的几何近似；把近似策略命名并版本化，不宣称完整真实物理模拟。
- 所有输出由稳定排序和固定 tie-breaker 决定，避免同一局面因 HashMap 遍历顺序不同而改变 AI 选择。

### 4.2 寻路

- **Dijkstra**：一次求解本回合速度预算内的全部可达位置，供移动与 AI 共同使用。
- **A***：仅用于目标明确的路径查询；heuristic 必须可采纳且与当前 metric 相容。若暂时无法证明可采纳，先用 Dijkstra。
- 节点至少包含 pose/height、movement mode 与所有影响后续边合法性的状态；当 facing 规则启用时，若转向改变可行动作，也将 facing 纳入节点状态。
- 每条边验证完整 footprint 与移动扫掠范围；按版本处理挤压（2014 Large 可挤过 5 尺开口，每尺额外 1 尺移动、攻击与敏捷豁免劣势、对其攻击有优势，按 PHB p.192；2024 窄口按 Difficult Terrain，无独立挤压劣势条款），不得穿墙、穿角或穿过不可通过体积，也不得主动结束在其他生物占位内。
- 返回路线应包含步骤成本、地形与高度变化、模式切换、触发器信息、预计是否可能引发借机攻击。路线仅是计划，执行时必须逐步重验，因为状态可能改变。
- 被迫移动（推、拉、坠落等）与生物自主花费速度的移动分离：可能共享几何查询，但不能一律消费移动预算或一律触发同样的动作。
- 无路径、路径过预算、目标被占用、路线中途被阻塞都要有结构化错误结果，不能静默把单位移到终点。

### 4.3 高度与飞行

- 使用独立的 FlightState / FlightMovement / FallResolver / VerticalInteraction 职责分离飞行能力、垂直可达性、失去飞行支持后的结算和地面交互。
- 以 profile 明确垂直步进、水平/垂直距离组合、上升/下降移动成本、悬停与天花板处理；这些是数字战场模型约定，除非规则明确规定，不要标记成原书唯一算法。
- 飞行生物的状态触发与坠落按对应 ruleset 的权威规则实现；坠落落点、碰撞、伤害、落地状态和多层空间的边界必须独立测试。
- 高度差在不同场景查询中的用途必须一致：射程、触及、视线、掩护、AOE、路径不是一条单公式。
- 缺失生物高度数据时使用可声明的简化高度 profile 和 provenance（来源/默认），不从体型名称臆测精确身高。

### 4.4 朝向与角度规则

- 任何 combatant 均可在扩展启用时持有 facing；2014 DMG p.252 的 Facing 是官方可选规则，2024 没有对应可选规则；不启用 facing policy 时，旧战斗命令、判定与路径结果必须与 legacy 行为一致。
- 面向方向的角度判定使用离散扇区与确定性边界，不使用浮点角度不等式来做关键规则。
- 正面/侧面/背面命中、包抄、转身成本、盾牌方向等全部作为独立 policy/house rule，可按战役数据启用，不得伪装成任一版本的默认 RAW（2014 仅为官方可选，2024 无此规则）。
- 法术锥形或其他有指定指向的效果以该次效果的 origin/direction 为输入，不得默认绑定于施法者长期保存的 facing。

## 5. 规则执行与存档兼容

### 5.1 唯一结算管线

AI/CLI action proposal → 参数与回合合法性检查 → 空间可达性与目标选择验证 → 规则引擎状态转移 → 触发器/反应/借机攻击按规则规定顺序处理 → 日志和持久化。确切事件顺序由 P5（TASK-0090）按冻结契约、现有引擎和 ruleset 落实；P1–P4 不得改变现有结算顺序。

- AI 不得把“评分最高”当作“合法”；所有行动在执行前重新验证。
- 模拟器用于估值时必须使用隔离的 state clone 与模拟随机流，禁止消耗正式游戏骰子。
- 概率模型须覆盖 d20、优势/劣势、重击、豁免、抗性/免疫/易伤等已有结算机制；没有实现某个复杂效果时，明确回退到 baseline/手动裁定，不假装完整评估。
- 每条移动边逐步处理借机攻击与进入区域触发器；不得先把角色瞬移到终点再补日志。

### 5.2 旧存档与版本

- 第一阶段先保存一组现有 Position / state JSON 的 golden fixtures，记录加载、重存与往返结果。
- 给新字段设置明确 serde 默认值；旧 2D Cell 加载后 z=0，旧 Zone 保持 Zone 语义。不允许将未声明的高度猜出来。
- 冻结 state 版本策略：若新增数据可安全使用默认值且 schema 不需升级，证明并写测试；若需要 schema bump，需提供单向迁移、备份/回滚行为和旧存档拒绝策略。
- 新空间语义采用显式 scene/profile 开关。无开关的旧战场保持现有 legacy 模式，避免升级二进制后已保存战斗忽然改变射程、覆盖或移动规则。
- 存档内自包含的内容快照必须保留必要 schema 与 profile 版本，保证未来程序可判断如何解释旧空间状态。

## 6. 战术 AI：从启发式到有限搜索

### 6.1 AI 分层

1. **Behavior / Objective Profile**：保留现有 ai_templates 参数，并扩展目标、纪律、保护/守点、撤退条件、警报响应、队友协同、风险偏好和对玩家未知信息的约束。
2. **Action Candidate Generator**：枚举有限且合法的候选——攻击/施法/能力、移动到可达位置、治疗/支援、撤退/防御、操作物件、守护目标。通过规则引擎的 legality/preview 接口过滤。
3. **Outcome Estimator**：以概率或可复现 Monte Carlo 估计攻击、豁免、伤害、状态、控制、资源消耗、位置暴露等后果；同一随机分布不得依赖正式游戏 RNG。
4. **Utility Evaluator**：对场景目标和行为特征进行显式评分。建议的效用项包括造成/避免伤害、击倒/控制价值、队友治疗和救援、资源消耗、被击倒风险、站位/掩体、目标推进、协同、撤退/警报代价和个性一致性。每项必须可解释并可测试。
5. **Planner**：先用单回合 utility planner 作为可测基准，再引入有限深度期望搜索/MCTS 等有预算约束的方法；无法证明完整最优时，产品说明使用“预算约束的近似决策”而不是“完整解决任意战斗博弈”。
6. **Execution Validator**：无论 planner 输出如何，行动执行前再做规则验证；非法动作需要拒绝并记录原因，然后回退尝试下一个候选。
7. **Telemetry / Debug**：提供仅在显式诊断模式中的候选摘要、主要效用分解、搜索预算、剪枝数、决策耗时与回退原因；不输出 DM 私密内容或玩家存档秘密。

### 6.2 搜索的范围与真实性

- 默认搜有限动作空间、有限回合深度和有限时间/节点数；控制分支爆炸。用候选动作剪枝、重复状态识别、渐进扩宽、top-K 候选和可选 beam/MCTS。
- 概率节点应该表达骰子/敌方行动的不确定性；机会结果用 exact expectation 或受控采样。己方真正执行的动作仍按真实掷骰机制产生结果，规划过程不能提前固定或消耗那次骰子。
- 对抗搜索必须允许敌方回应，不只把所有友方动作连续排在一起。团队协同可以使用 team action selection，但必须有时间上限。
- 隐藏状态 / DM 秘密不直接暴露给 NPC AI。只用当前生物按其感官与信息状态可观察的 world view；将来若支持部分可观测规划，使用 observation/belief state，不用读取全局 DM 私有对象。
- 确定性要求：固定 seed、相同状态、相同版本与配置产生可复现的候选排序和统计结果；跨版本可通过算法版本标识区分。
- 保留 heuristic planner 作为低算力和搜索失败的 fallback，明确记录回退原因；预算超限必须可预测地终止。

## 8. 测试与量化验收

### 8.1 几何与规则测试

- 大型、巨型及更大 footprint 在门洞、走廊、转弯、楼梯与狭窄空间中的合法性，按对应版本的挤压 / 穿越规则判定（2014 允许挤压，2024 窄口按困难地形），不能统一写成“不可通过”。
- 边界格、墙角、对角步、困难地形、上/下降、不同运动模式、被占据的目标位置。
- 目标在半掩体/四分之三掩体/完全掩体后；不同高度、低矮障碍、天花板与多条可见线段。
- Cone/cube/cylinder/emanation/line/sphere 的边界与目标体积相交；目标部分处于影响区域和完全遮挡的情况。
- 触及与射程、移动代价与实际距离、垂直距离、Zone graph 距离不会发生混算。
- 飞行速度归零、失能、倒地、悬停、坠落、障碍碰撞、落地与强制移动。
- Facing 未启用时保持 legacy；2014 可选 Facing 的 8 向边界表、转向与攻击弧单独测试，2024 默认 profile 保持关闭。
- 所有移动逐边触发借机攻击、区域触发器和地形结果；行动被中断后无瞬移/重复结算。

### 8.2 持久化与规则分层

- 当前发布版状态 JSON 的 golden fixture 可加载，z 缺失默认值正确，重存不丢失未知/已知内容。
- ruleset=2014 和 ruleset=2024 分别跑规则测试；common + 选中版本数据加载正确，另一规则目录不被混入。
- 旧战斗数据和未启用 3D 的地图保持旧语义；场景 profile 启用后新模型行为可解释。
- 所有新增数据 schema 在 content check 中验证；错误消息指出文件/字段/无效配置。
- 书籍原文、非 SRD 数据、实际玩家存档和 DM 秘密不得出现在测试 fixture、Issue、PR 或日志。几何测试只使用合成名称、人工数据与合成地图。

### 8.3 AI 质量与性能指标

每个 synthetic encounter 至少记录：动作合法率、选中候选的预估/实测效用差、胜率/平局/超时、回合数、双方剩余 HP、资源余量、决策耗时 P50/P95、扩展节点、fallback 次数与不可用候选原因。

- 比较组至少包含当前启发式、单回合 utility、有限搜索三个基线，使用同一组场景、相同随机 seed 集和相同候选可用性。
- 不能只以胜率判断 AI：加入“能否保护/撤退/守点/阻止目标”等目标完成率，避免所有角色变成高伤害贪婪策略。
- 在 CI 中跑小型确定性测试与短基准；完整 Monte Carlo 性能实验按专门任务执行，不把不稳定的 wall-clock 作为普通单元测试断言。
- 设定预算上限（节点、深度、时间或其组合），并以实测结果选默认值；无数据前不宣称已有性能目标。
- 性能基准报告记录硬件/OS、commit SHA、seed、配置与命令。性能回退超过门槛时先分析，不得靠删减测试或降低正确性通过。

## 9. 回退、风险与禁止事项

- 每一阶段可独立合并并保持程序可构建；不得提交无法编译的中间状态。
- Spatial profile / planner 可配置关闭；出现不一致时默认回退 legacy 2D + 当前启发式，而不是改写旧存档位置或将不确定结果当成合法。
- schema 变更必须有明确 migration、可恢复备份与旧版拒绝策略；不允许无说明地重新解释既有坐标。
- 不加入新的外部服务，不新增依赖，除非项目所有者先行批准。
- 不将真实规则书正文提取成公开结构化库；源码中的 ruleset-specific 代码只实现通用规则，内容继续由合规数据驱动。
- 不硬编码某只怪物的体积、攻击方式或 AI 对策；如数据缺失，使用可审计的通用缺省并标明来源。
- 不把 Facing、精确碰撞物理、真实空气动力学、全局最优博弈、所有法术自动化承诺为首版目标。
- 不以 AI 搜索结果为由越过引擎校验，不用正式骰子为候选动作“试掷”，不读取 AI 不应知道的秘密。
- 发生规则歧义、2014/2024 语义冲突、旧存档不可安全迁移或性能/质量目标冲突时，暂停相关任务，提交证据和选项进入 NEEDS_HUMAN_DECISION。
