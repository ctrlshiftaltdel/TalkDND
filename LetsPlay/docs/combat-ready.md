# 准备动作（Ready）

这页给 DM 用。准备动作让玩家在自己的回合用**一个动作**等待一个可感知的情况，并在情况发生时用**反应**执行一个响应。两版（2014 / 2024）的 Ready 规则相同，引擎不为版本写分支。所有命令都在 `LetsPlay/` 里运行，`CS=bin/combat-sim`。

## 什么时候用

玩家说“我准备动作：敌人一进来就砍它”“我举盾等着，谁打我我就还手”“门一开我就冲进去”时，用 `ready`。不要把它写成备注或让玩家下回合再补动作；设置时就会扣掉本回合的动作。

## 设置

```sh
# 武器攻击：没写 --target 时，响应目标就是触发者
$CS --state fight.state.json ready "角色名" \
  --on attacked --trigger "敌人攻击我" --attack longsword

# 徒手打击
$CS --state fight.state.json ready "角色名" \
  --on enter-reach --trigger "敌人进入触及" --unarmed

# 能力/法术：必须是“动作”启动的能力；范围能力要写 --target
$CS --state fight.state.json ready "角色名" \
  --on ability --trigger "邪教徒施法" --ability sacred-flame --target "邪教徒"

# 移动到可达位置：区域用 --zone，网格用 --to X,Y
$CS --state fight.state.json ready "角色名" \
  --on manual --trigger "门一开就退到走廊" --zone corridor

# 查看
$CS --state fight.state.json status
$CS --state fight.state.json status --json
```

- 同一生物同时只能有一个准备动作；已经准备时再设置会失败，不会覆盖原来的响应。
- 没有动作、失能、死亡、休眠、或不能使用反应时，`ready` 会失败，且不扣动作。
- `--trigger` 是给日志看的情况描述，会压成一行并限制长度。**不要把 DM 秘密、存档正文或书里原文写进去。**
- `--on` 决定自动触发的方式；不写时是 `manual`（只能由 DM 显式触发）。

## 触发方式

| `--on` | 什么时候自动触发 |
|--------|------------------|
| `manual` | 只等 DM 的 `trigger` 命令。 |
| `enter-reach` | 敌人移动（含被推/被拉）从响应触及/射程外进入范围内。 |
| `attacked` | 敌人完成一次攻击后。 |
| `ability` | 敌人完成一次能力/法术之后。 |
| `turn-start` | 敌人开始回合时；准备者自己的回合开始只会让准备过期。 |

玩家描述的情况不在表里时，用 `manual`，等事情发生由 DM 触发：

```sh
# 显式触发；--source 是引发触发的人，响应没写 --target 时用它当目标
$CS --state fight.state.json trigger "角色名" --source "敌人名"

# 主动取消准备（不触发、不消费反应）
$CS --state fight.state.json ready-clear "角色名"
```

## 结算与过期

- 准备**法术或有消耗的能力**时，设置 Ready 当场扣除法术位/资源；需要专注的法术当场开始专注。设置失败（资源不足、目标非法、能力不能准备）时动作、资源、专注都不变。
- 触发时只释放已经准备好的法术/能力：**不再扣法术位/资源，也不再重新开始专注**；成功才扣反应。
- 触发时先检查：准备是否还在有效期内、反应是否已用、目标和响应是否仍合法。失败会写清原因并保留准备、已付资源和专注，不扣反应。
- 准备在设置者**下一次回合开始时**过期，日志会说明。`ready-clear` 可提前清除。
- 未触发、过期、`ready-clear`、死亡、0 HP、失能、休眠都**不退法术位/资源**。如果这次准备开始的专注还在，会结束它并写日志；其他来源的专注不受影响。
- 准备专注法术后又施放另一个专注法术：新专注按现有规则替换旧的，准备随之失去，法术位不退。专注被伤害打断时，准备好的法术已经失效，触发会被拒绝且不退位。
- 死亡、0 HP、失能、休眠会清除准备；死亡日志在专注清理之前写。
- 响应走正常引擎路径：武器/徒手攻击按触及、射程、视线、掩护、魅惑来源等校验；能力按正常目标/范围校验；移动按正常路线逐步走，不瞬移。
- 反应每轮恢复一次（与引擎现有的反应记账一致）；同一轮已经用过反应的生物不能触发准备。

## 常见裁定

- 准备的是“攻击”时只结算一次攻击，不享受额外攻击的多段；额外攻击只属于 Attack 动作。
- 准备的武器必须在角色数据里有；准备的能力必须是“动作”启动。附赠动作、反应、被动和自由能力不能准备。
- 范围能力在设置时就要给 `--target`（区域名、`X,Y` 或生物名），触发时重新校验。
- 准备好的移动被锁门/墙挡住时，角色会停在阻挡处，日志写明；这次响应仍算触发并扣反应，不会回滚已经走过的路。
- 显式 `trigger` 被拒绝时命令仍会成功返回，但会把拒绝原因写进战斗日志；看到 `refused` 就按日志处理，不要重复触发。
- 设置 Ready 时就扣法术位/资源并开始专注，不是触发时才结算。玩家问“还没触发能不能退位”时，答：不能；RAW 是设置时就施法，未触发/过期也损失这次法术位。

## 与存档

- 准备动作存在战斗状态里；旧战斗状态没有这个字段时按“没有准备”加载，`STATE_SCHEMA_VERSION` 仍为 1，不需要 `talkdnd` 迁移。
- 旧的 `attack --force`、`use` 命令保持原样；没有准备时新逻辑不改变任何结果。
- 规则数据不需要新增条目：两版共用同一个 Ready 形状。若以后版本出现差异，再由数据层表达，不改引擎分支。
