# 选项写法：只从玩家已知的信息出发

> 本文件是 `AGENTS.md`「选项写法」的完整说明。路径都相对于游戏文件夹。`T=bin/talkdnd`。

DM 每幕结尾都要给 2–4 个选项，但选项不是“DM 知道的所有做法”，而是“角色在当前处境下想得到、看得见、听得说的做法”。写错选项和说错描述一样是剧透：它会把玩家还没发现的暗门、DC、幕后安排直接摆到桌面上。

## 1. 唯一的已知信息清单：`known`

写选项前先运行：

```
$T known
```

它列出：

- `reveals.yaml` 里已揭示的事实（角色通过检定、对话、阅读、观察真正知道的）；
- 已经给玩家看过的资料图（`handouts.yaml`）；
- 已经识别的怪物/物品（`identified.yaml`）；
- 已经出场或隐藏面已揭示的原创内容；
- 队伍角色卡基础信息；
- 当前章节和 `$T scene` 记录的当前地点。

`$T start` 会打印这份清单的压缩版。换场景时运行 `$T scene "<地点>"`，它写入 `progress.yaml` 并立刻打印完整 `known`。**不在清单里的专名、地点、人物关系、暗门、陷阱、DC，都不能出现在描述或选项里。**

## 2. 不报具体 DC 和未公开的做法

检定 DC 是 DM 的幕后信息。除非：

- 玩家已经从书里、NPC 口中或之前的检定中得知（并已 `reveal add`）；或者
- 房规明确公开 DC（写进 `house-rules.md`，开局前或两次会话之间商定）。

否则只能说难度感，不能说数字。

| 错 | 对 |
|----|----|
| “这扇门用盗贼工具 DC 20 或力量 DC 20 就能再打开。” | “你们只知道机关刚才被触发过；怎么让它再动，角色还没头绪。可以检查门缝，或去问见过的人。” |
| “说服馆长要 DC 18。” | “馆长很警惕，空口白话恐怕不行；你们可以拿邀请函、找他的把柄，或者换个时间再来。” |
| 选项：“用 DC 15 的察觉找出暗门。” | 选项：“检查书架和墙面的接缝 / 问馆长最近有没有改建 / 先去别的房间找线索。” |

允许说“看起来很难”“需要工具”“得先找到机关”，不允许替玩家决定“用盗贼工具 DC 20”。

## 3. 未发现的隐藏内容不能进选项

暗门、密室、陷阱、隐藏敌人、宝物位置，必须先被角色发现（调查、察觉、打听、法术、NPC 告知），并记进 `reveals.yaml`，之后才能作为选项或描述出现。玩家可以主动说“我检查书架”，这是玩家的自由；但 DM 不能把“书架后有暗门”写成现成选项。

| 错 | 对 |
|----|----|
| 选项：“从书架后的暗门离开。” | 选项：“检查书架 / 问馆长 / 沿走廊找别的出口。” |
| 选项：“用银钥匙打开北墙的密室。” | 选项：“试手里的钥匙 / 检查北墙 / 问守卫钥匙是做什么的。” |
| “你们注意到地毯下有暗门。” | “你们可以检查房间；想确认地面有没有问题，就说说怎么查。” |

## 4. 模糊情报保持模糊

玩家拿到的是草图、传闻、半句话，就只给到这个精度。DM 不能用自己的全书知识替玩家“补全”成准确结论。

| 错 | 对 |
|----|----|
| “北墙左边第二扇门有警报。” | “草图只标了北墙有两扇门，警报装在哪扇你们不确定。” |
| “馆长就是幕后黑手。” | “馆长最近经常深夜留在馆里；是不是和这件事有关，你们还没有证据。” |
| “地下室有 3 只守卫。” | “你们听说地下室有人看守，具体几个、什么装备不清楚。” |

如果玩家想确认，就让他们调查、感知、打听或用法术；结果再 `reveal add`。

## 5. 关键节点跑 `guard`

把准备发给玩家的选项列表（或整段叙述）交给程序检查：

```
$T guard "选项一：检查书架。选项二：问馆长。选项三：沿走廊找出口。"
```

- 输出「剧透词：X（建议改写为玩家已知的说法）」表示草稿里有未揭示的秘密词或隐藏面。
- 退出码 1 表示有命中；0 表示干净。
- 管道输入也行：`echo "<草稿>" | $T guard -`。
- 命中就改写措辞，或者让玩家先调查；不要因为被提示就删掉线索、改 DC 或惩罚玩家。

秘密词来源包括 `dm-secrets.md`、`dm-plan.md` 的 `- term: X` / `[[X]]`、未来章节标题、DM-only 小节、原创 `hidden` 和 `$T secret add`。已揭示的词会自动排除。

## 6. 名称要按“已识别”来写

未识别的怪物/物品不能直接叫真名。用外貌描述，例如“一只大型野兽”“一个披着灰斗篷的瘦高身影”。

```
$T identify --appearance <东西> "<外貌描述>"   # 识别前对玩家使用的描述
$T identify <东西> --how check|reveal|lore --reason "<怎么知道的>"
```

给玩家看战斗记录时用 `$CS ... --player`：未识别怪物显示外貌，已识别的显示真名；DM 自己看的视图不要加 `--player`。

## 7. 三个完整场景（改自常见劫案式冒险，非原文）

### 场景 A：只揭示了“机关被触发过”

错误：

> DM：“这扇门用盗贼工具 DC 20 或力量 DC 20 就能再打开。”
>
> 选项：A. 盗贼工具 DC 20 开门；B. 力量 DC 20 撞门。

问题：玩家只知道机关触发过，不知道复位方法，更不知道 DC。

正确：

> DM：“你们只看到门边的铜环缩回去过，不知道它连着哪里。要再试一次，得先弄清机关怎么动。”
>
> 选项：A. 检查铜环和门缝；B. 找馆里的人问这扇门；C. 先去别的房间找工具。

### 场景 B：暗门还没被发现

错误：

> 选项：A. 从书架后的暗门离开；B. 回大厅。

问题：暗门是否存在、在哪，角色都还没发现。

正确：

> 选项：A. 检查书架和墙面；B. 回大厅；C. 问馆长书房能不能参观。

玩家选 A 后再按调查结果决定是否发现暗门；发现了才 `reveal add`，下一次选项里才可能出现暗门。

### 场景 C：只有一张粗略草图

错误：

> DM：“北墙左边第二扇门有警报。”
>
> 选项：A. 拆掉左边第二扇门的警报；B. 走右边那扇。

问题：草图只显示北墙有两扇门，没有标警报位置。

正确：

> DM：“草图只画了北墙有两扇门，旁边打了个问号。警报装在哪扇、有没有装，你们不确定。”
>
> 选项：A. 先观察两扇门附近的人流；B. 问馆里的仆役；C. 从走廊另一头绕过去看看。

## 8. 写选项前的检查表

1. 这句话里的每个专名，`known` 里都有吗？
2. 有没有说出未揭示的 DC、做法、暗门、陷阱、隐藏敌人？
3. 模糊情报是不是被我说成了确定结论？
4. 选项是不是只有角色想得到、做得到的做法？
5. 关键选项跑过 `$T guard` 吗？
6. 这一幕有没有新事实需要 `$T reveal add`？
