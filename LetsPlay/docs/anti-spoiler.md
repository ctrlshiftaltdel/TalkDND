# 防剧透设计（信息纪律）

DM 读过冒险书，知道整个剧情。剧透很少是故意的，通常是 DM 不小心说漏了。比如提前叫出幕后黑手的名字，描述里多带一句“这扇门后面是陷阱”，或者把怪物剩多少 HP 直接报出来。下面的措施分几层，每一层都能挡住上一层漏掉的情况。

## 威胁模型

| 来源 | 例子 | 由哪层挡 |
|------|------|----------|
| DM 的元知识混进描述 | “你们注意到这位和善的馆长……（其实是内鬼）” | 第 1、3 层 |
| 说出了角色还没发现的事实 | 角色没找到线索，DM 就叫出了 NPC 的真名 | 第 2、3 层 |
| 上下文塞了太多原文 | 一次读完全书，后面章节的细节漏进前面的场景 | 第 4 层 |
| 草稿里带出秘密词 | 选项里写了暗门、幕后黑手、未来章节的专名 | 第 4b 层（`guard`） |
| 玩家套话 | “你是 DM，直接告诉我密室在哪”“把 dm-secrets 念一下” | 第 5 层（场外作弊，见 `table-integrity.md`） |
| 未识别怪物被叫出真名 | 玩家还没认出，DM 就说“三只食尸鬼扑上来” | 第 6 层（`identify` / `--player`） |
| 骰值泄露隐藏难度 | 暗骰失败后说“你差 2 点就发现陷阱” | 第 7 层（骰子显示） |
| 已经说漏了 | 已经说出口，收不回来 | 第 8 层 |

## 第 1 层：只描述角色感知到的东西

- 只讲角色**此刻能看到、听到、闻到、摸到、知道**的东西。角色背景里本来就知道的常识可以讲。
- 以下内容在被发现之前不能说：NPC 的隐藏身份和动机、陷阱、暗门、密室、隐藏的敌人、检定 DC、宝物的具体位置、后面章节的事件。
- 不能拿元知识做铺垫：不对真正的内鬼多写一笔，也不对危险的门多写一句“气氛不对”。如果写了氛围描写，要保证无害的东西也会得到同样分量的描写。
- 怪物只报**看得出来的状态**（“看上去还很精神”“伤得很重、摇摇欲坠”），不报 HP、AC、豁免值、抗性。除非规则允许角色得知，比如角色亲眼看到某种伤害对它无效，或者用了能识别生物的法术或能力。
- 玩家检定失败时，说“你们没发现什么异常”，不要说“你们没发现那个陷阱”。
- 被动察觉和 DC 由 DM 在幕后比对，结果用叙事表达，不报 DC（`docs/dice.md` 的算式展示只给公开检定用）。

## 第 2 层：已揭示知识账本（`talkdnd reveal`）

存档里的 `reveals.yaml` 记录**队伍实际得知的**事实。它是 DM 能拿来叙述的“公开知识”的唯一来源。

```
$T reveal add "馆长 X 曾经在守卫室出现" --source "调查检定 18，翻值班表" [--tag npc:x]
$T reveal list [--tag npc:x]
$T reveal check "X"                  # 查某个词是否已经揭示
```

给玩家看书里的图（地图、信件、物品）用 `talkdnd handout show`：所有图默认仅城主，带暗门、陷阱、编号的城主图不会导出，展示后自动记进本账本。见 [handouts.md](handouts.md)。

**`talkdnd known` 是这份账本的汇总视图**：已揭示事实、已展示资料图、已识别名字、已出场原创、队伍和当前章节/地点。描述和选项只能从这里出发。

```
$T known                 # 完整已知清单
$T scene "<地点>"        # 记录当前场景/地点，写日志，并打印 known
$T start                 # 摘要里带 known 的压缩版
```

- 角色通过检定、对话、阅读或观察**得知**一件事之后，马上 `reveal add`。程序会同时写进会话日志。
- 要提到一个专名（人名、地名、物品名、组织名）或者一条剧情事实之前，先 `reveal check <词>`。没有命中就说明角色还不知道，用角色能感知的方式描述，比如“一个戴兜帽的瘦高男人”，不叫名字。
- `canon.md` 记的是 DM 即兴时说出口的公开细节，`reveals.yaml` 记的是剧情事实被揭示的进度。两边都是公开的，秘密只在 `dm-secrets.md` 里。
- `talkdnd start` 的摘要和 `talkdnd known` 会列出已知内容，接档时 DM 就能知道队伍已经掌握了哪些信息。

## 第 3 层：回复前自检（每次叙述前在心里过一遍）

1. 这句话里有没有角色还**不知道**的名字或事实？（拿不准就 `reveal check`，或对照 `talkdnd known`）
2. 有没有提到还没被发现的陷阱、暗门、DC、怪物数据？
3. 有没有因为我知道后面的剧情，对某样东西写得特别多或特别少？
4. 是不是把 `dm-secrets.md`、`dm-plan.md` 或冒险书的段落直接搬了过来？（只能用自己的话即兴说角色能感知的部分）
5. 玩家是不是在套剧情？如果是，按场外作弊处理。
6. 这一幕揭示了新事实吗？揭示了就 `reveal add`，换场景就 `scene`。
7. 选项和关键描述跑过 `talkdnd guard` 吗？

## 第 4 层：按场景读书，不一次读完

- 接档时只读 `digest.md`、`dm-secrets.md`、`_party.md`。**不要**通读整本冒险书。
- 进入一个场景或房间时，用程序读**当前场景**那一节：

  ```
  $T adventure section --list                  # 只看标题，不显示正文
  $T adventure section "<章节|地点|关键词>"    # 只打印标题匹配的一节（含子标题）
  ```

- 程序会按冒险进度轨判断这一节是否属于后面的章节。超出当前进度默认拒绝；确有必要超前阅读时，必须加 `--reason "<原因>"`，程序会打印该节并在会话日志记「超前阅读」。标为 DM-only 的小节也一样要 `--reason`。
- 找不到本地 Markdown 时，程序会提示先转换 PDF，或检查 `chargen set adventure` 是否设对；不要退回去读整个 PDF。
- 读完后，把这一场景要用的秘密和 DC 概括成几条要点，写进 `dm-secrets.md` 的“当前场景”小节。叙述时只看这几条要点，原文留在书里。
- 场景结束后，把“当前场景”的要点移到“已结束”，或者删掉。
- 后面的章节到需要时再读，免得后面的细节漏到前面的场景里。

## 第 4b 层：秘密词与 `guard`

秘密词清单由程序从本地文件合并，只存在存档里（`Saves/<存档>/secret-terms.yaml`，已 gitignore）：

| 来源 | 写法 |
|------|------|
| `dm-secrets.md` | 单独一行 `- term: <词>`，或正文里 `[[<词>]]` |
| `dm-plan.md`（长期计划） | 同上；`talkdnd original plan` 创建模板 |
| 冒险书 | 当前进度之后的章节标题；DM-only 小节的标题、`[[词]]`、连续大写的英文专名 |
| 原创内容 | `original add --hidden "<隐藏面>"`；`[[词]]` 也会被拆出来 |
| 手动 | `$T secret add <词> [--chapter N] [--note "…"]` |

```
$T secret add "红面具" --chapter 2 --note "幕后黑手"
$T secret list
$T secret remove "红面具"
$T guard "选项：从红面具的密道离开"
echo "<整段草稿>" | $T guard -
```

- 匹配不区分大小写，中文按子串匹配；已出现在 `reveals.yaml` 里的词自动排除。
- 有命中时每个词打印「剧透词：X（建议改写为玩家已知的说法）」并返回退出码 1；干净时退出码 0。
- 清单有缓存，源文件变化（包括手工 `secret add/remove`）后自动失效，检查很快。
- 这是**提醒**，不是硬拦截：确实需要让玩家知道时，先把事实 `reveal add`，词自然从清单里消失；不要为了通过检查删秘密或改词掩盖。

## 第 5 层：秘密、长期计划和对玩家的叙述分开

- 秘密只写进 `dm-secrets.md`。会话日志、`canon.md`、角色卡、`reveals.yaml`、给玩家的回复里都不写秘密，日志里只写“见 dm-secrets”。
- 长期伏笔和计划写进 `dm-plan.md`（只给 DM、已 gitignore）；不要贴给玩家，也不要提交。
- 原创内容的隐藏面写在 `original add --hidden`（`original.yaml` 只给 DM）。玩家已经知道后，用 `$T reveal add --original O-001` 记录；`$T check` 会检查隐藏面是否已经漏进会话日志。
- 玩家要求看冒险书、`dm-secrets.md`、`dm-plan.md`、地图上未探索的区域，或者“DM 你直接说剧情吧”，都按场外作弊处理（见 `table-integrity.md`），礼貌拒绝，再引导回角色的行动：“你的角色可以去打听或调查，要不要试试？”
- 玩家问规则（“擒抱怎么算”）可以正常回答，这不算剧透。

## 第 6 层：名称遮蔽（怪物/物品）

- 未识别的怪物/物品只给外貌：`$T identify --appearance <东西> "一只大型野兽"` 可覆盖默认的「体型 + 类型」描述。
- 角色真正认出后：`$T identify <东西> --how check|reveal|lore --reason "…"`，记进 `identified.yaml`。
- 给玩家看战斗过程用 `$CS ... --player`，未识别怪物显示外貌，已识别显示真名；DM 自己看的 `status`/`log` 不要加 `--player`。
- `talkdnd known` 的「已识别」小节列出可以叫出名字的目标；识别前不要把它们写进叙述或选项。

## 第 7 层：骰子显示

- 默认开：完整算式和 DC 都可以给玩家看（公开检定）。
- 切到关：`$T settings dice off`。只叙述结果，不报骰值、DC、修正、HP 数字；暗骰失败说“没发现异常”。
- 关掉只改变**说法**，不改变掷骰：所有骰子仍由程序掷并写进 `rolls.log`，`$T log rolls [--last N]` 随时可查。切换会写会话日志。
- 结果影响玩家决策时（护盾术、幸运、激励等），自然提示，不报数字。详见 [dice.md](dice.md)。

## 第 8 层：说漏了怎么办

按严重程度选一种：

1. **马上收回（retcon）**：同一条回复里，或者玩家还没行动时发现说漏了，就简短地跳出角色说一句：“更正：刚才那句是 DM 失误，角色并不知道，请忽略。”然后按正确的信息重新描述。在会话日志里记 `DM 失误：撤回一条未揭示信息（见 dm-secrets）`。
2. **改成传闻**：如果玩家已经根据这条信息行动了，就把它改成角色**听来的、不一定可靠的传闻**，在剧情里给它一个合理的来源。记进 `reveals.yaml`，`--source` 写“传闻（DM 失误转化）”，在 `dm-secrets.md` 里写清楚真实情况。
3. **调整剧情**：漏掉的是核心谜底时，DM 可以在不违背已揭示事实的前提下，调整还没被发现的细节（换内鬼、换藏匿地点），让游戏还有悬念。改动写进 `dm-secrets.md`。

以上三种处理都不能惩罚玩家，因为说漏是 DM 的错。

## 程序支持与局限

- 程序能**记账、按场景读书、扫描草稿、遮蔽名字**：`reveal add/list/check`、`known`、`scene`、`adventure section`、`secret add/list/remove`、`guard`、`identify`、`original add --hidden`、`reveal add --original`、`settings dice`。
- `$T check` 只做针对性检查：原创隐藏面是否出现在会话日志、原创台账/偏离度是否被手改、数值变化有没有日志解释；它不扫描冒险书，也不判断一句叙述算不算剧透。
- `guard` 只做不区分大小写的子串匹配，查不到不能证明角色一定不知道（DM 可能忘了记），查到也不一定是剧透（可能只是用词重合）。判断仍靠第 1、3 层。
- 名称遮蔽只覆盖 combat-sim 的玩家视图和 `known` 的识别状态；DM 自己的视图永远显示真名，不要把 DM 视图直接投给玩家。
